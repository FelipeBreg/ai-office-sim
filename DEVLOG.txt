COMMIT #111 — Full Codebase Audit & Security Fixes
================================================================================
Date:     2026-03-03
Scope:    packages/api, packages/db, packages/ai

Performed comprehensive 4-part audit (DB schema, tRPC routers, frontend, worker/queue).
Audited ~33 routers, 31 schema files, 22 auth pages, 12 workers, 4 backend packages.

CRITICAL FIXES (Security):
  - members.ts: Cross-tenant privilege escalation — updateRole and remove mutations
    did not scope user lookup/update/delete to orgId. An admin from Org A could
    theoretically change roles or delete users in Org B. Fixed by adding
    eq(users.orgId, ctx.org!.id) to all WHERE clauses (3 locations).
  - community.ts: installAgent/installWorkflow used projectProcedure instead of
    adminProcedure, allowing viewers/managers to install agents. Changed to adminProcedure.
  - resume.ts: Sandbox mode bypass — after approval resume, mutation tools executed
    for real even when sandboxMode=true. Added sandbox intercept checks in both the
    pending tool execution path and the continuation loop (matching executor.ts pattern).

MEDIUM FIXES (Data/Logic):
  - documents.ts: listByAgent with agentOnly=false was identical to agentOnly=true
    (never returned project-wide docs). Fixed by adding or(eq(...), isNull(documents.agentId)).
  - messaging.ts: ILIKE search did not escape %, _, \ wildcard characters (same fix
    already applied to community.ts but missing from messaging search).
  - workflow-templates.ts: previewDeploy used protectedProcedure but accessed ctx.project!
    (which could be null). Changed to projectProcedure.
  - community.ts (schema): publishedById and orgId FK references had no onDelete rule
    (PostgreSQL defaults to NO ACTION, blocking user/org deletion). Added onDelete: CASCADE.
    Migration SQL: packages/db/src/migrations/community-fk-ondelete.sql

AUDIT FINDINGS (NOT FIXED — backlog):
  DB Schema:
    - Missing indexes on several FK columns (conversationMessages.conversationId solo,
      emailMessages.connectionId, whatsappMessages.connectionId, workflows.createdBy, etc.)
    - Enums defined inline in marketing-campaigns.ts, brand-touchpoints.ts, financial-records.ts
      instead of centralized enums.ts
    - deals.ts dual stage system (enum stage + FK stageId) — potential data drift
    - Missing workflowRuns.status index (common orchestrator query)

  tRPC Routers:
    - financialRecords.list, strategies.list, marketing-campaigns.list have no pagination
    - approvals.ts: enforceResourceLimit + insert not atomic (race condition on concurrent requests)
    - atlas.ts: Tool execution errors swallowed without logging
    - orchestrator.ts: team input is z.string() not enum-validated

  Worker/Queue:
    - Calendar reminder, calendar recurrence, email inbound, cleanup jobs never enqueued
      (workers exist but no repeatable BullMQ jobs registered in index.ts)
    - LLM Helicone timeout 5s too low — most Claude calls take 10-60s
    - notification.worker.ts hardcodes riskLevel: 'medium'
    - approval-check.ts: checkApprovalRule() exists but never called

  Frontend:
    - Calendar page: all strings hardcoded in English (no i18n)
    - Messaging page: all strings hardcoded in English (no i18n)
    - Header: dead '/analytics' entry in routeToNavKey map

TypeCheck: All 13 packages pass.

COMMIT #69 — Fix Dashboard/Deals/Finance 500 Errors (Date Serialization Bug)
================================================================================
DATE: 2026-03-01
HASH: 32d54c4
PHASE: Post-Phase 3 — Bug Fix

ROOT CAUSE:
  The postgres driver (v3.4.8) cannot serialize JS Date objects passed
  directly in drizzle's sql`` template literals. The pattern:
    sql`${column.createdAt} < ${since}`
  crashed with: "The 'string' argument must be of type string or Buffer.
  Received an instance of Date"

  Drizzle's built-in operators (gte, lt, etc.) handle Date serialization
  correctly, but raw sql`` templates pass values straight to the driver.

  This broke 3 endpoints on the Dashboard page:
    - dashboard.general (General tab) — 500
    - deals.kpis (Commercial tab KPIs) — 500
    - financialRecords.summary (Finance tab) — 500

FIX:
  Replaced 5 instances of sql`${col} < ${since}` with lt(col, since):
    - dashboard.ts: 3 instances (prevAiCost, prevDealKpis, prevFinSummary)
    - deals.ts: 1 instance (previous period deal KPIs)
    - financial-records.ts: 1 instance (previous period summary)

FILES: 3 changed, +8 -7
  - MODIFIED: packages/api/src/routers/dashboard.ts
  - MODIFIED: packages/api/src/routers/deals.ts
  - MODIFIED: packages/api/src/routers/financial-records.ts
